Decision workflow

The six steps to go from “I want to play a lot of poker” to a booked, verified trip. Work them in order — each step blocks the next until its inputs exist. Open items are tracked in Questions.

  1. Fix trip dates and the nightly budget/quality floor. Everything downstream (rate quotes, event shortlist, day plan) is date-specific. Until dates exist, hotel totals stay blank (FL09). Use the trip calculator to set the budget.
  2. Confirm entry policy for candidate events. Every candidate's structure sheet has been read (fee split, guarantee, late-reg printed; no re-entry/rebuy/add-on wording). Because no sheet prints “single entry” (FL13), get written maximum-entry / no-rebuy / no-add-on confirmation from tournament staff before treating an event as a strict freezeout. Remove anything that allows extra entries from the strict path — those are already quarantined in the spend-more bucket.
  3. Compare surviving events on the verified fields. Guaranteed pool (labelled: bounty guarantees include total bounties), total entry fee (house + staff + prize split), starting stack / level duration, payout percentage, and daily schedule fit. Rank only after total entry fee and guarantee are confirmed — the ratio column does this descriptively.
  4. Get itemized hotel totals for the same stay; check the walk. Checkout total, nightly average, resort fee + tax, parking, cancellation deadline, rate timestamp — compared like-for-like. Verify each hotel–venue route under 30 minutes via the route links.
  5. Build one event per day first. The day plan assigns a primary per day plus a conditional evening fallback that is only reachable if the earlier event exits before the later late-reg closes. Overlap badges mark impossible sequences.
  6. Reconfirm before nonrefundable payment. Re-check official schedules, rates and policies the day you book — or let the scheduled re-check flag changes for you. Never book nonrefundable against a flagged row.

Standing rules

  • No double buy-ins, re-entries or add-ons in the strict path — anything that lets money buy advantage is listed separately with its clause.
  • Never infer or fill values: if an official source doesn't print it, the cell is blank and flagged.
  • Guarantees are descriptive, not forecasts. Ratio = guaranteed pool ÷ total entry fee.
  • Bounty, flight and satellite events are labelled and ranked separately.
  • Every row carries its source link and its last-checked date.

Every table row links its official venue source. Values that cannot be confirmed from an official source are blank and flagged on Flagged for review. Guarantees are not forecasts. Ratio = guaranteed pool ÷ buy-in, descriptive only.
