  `dayPlan[].recurring` entry. The earliest start anywhere in the published data is
  **9:00 AM** (Horseshoe daily tournament). No 8:00 AM start exists, so the 8 AM all-day

- **Ratio arithmetic.** `ratio = guarantee / buy-in`, rounded to one decimal place by the
  builder (`scripts/data_source.py`). This is a deliberate display rounding, not a defect.

## Defect found and fixed this session

**`scripts/daily_feed.py` overwrote one room's snapshots.** A room that publishes more
than one schedule page (the Venetian feed reads the DSE IV page, the DSE NYE page and the
poker-room page) wrote every page to the same `<room>-<date>.txt` filename, so the last
page overwrote the earlier ones and only the last page's text survived on disk. The
`index.json` hash record for each page was still correct, but the durable text snapshot
that a morning run is meant to compare day-over-day was lost for the earlier pages.

**Fix.** Each page now writes its own dated snapshot keyed by a short digest of its URL
(`<room>-<date>-<8-char-url-digest>.txt`), so pages never collide. Added
`tests/test_daily_feed_snapshots.py` (2 cases) which runs the feed with a fake fetcher and
asserts distinct snapshot files and index entries for a multi-page room. The scheduled
`checks.yml` workflow regenerates `site/feed/**` on the next run (it is triggered by a
change to `scripts/daily_feed.py`), so the committed feed artifacts will be rewritten with
the corrected naming.
